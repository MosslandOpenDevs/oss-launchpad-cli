# Preset web-app one action check

Use this note before widening the first visible `web-app` proof beyond the landing form and first result card.

## Rule

Keep the first UI proof tied to one believable user action:

- one form submission,
- one visible result card,
- one clear download or handoff target.

## Why it matters

This keeps early demos aligned with the UI-first and stability-first proof loop instead of drifting into an unfinished multi-screen story.

## Quick review

- Does the landing brief still describe one primary action?
- Does the information architecture keep that action above secondary navigation?
- Does the demo script reopen the same proof without extra setup?
