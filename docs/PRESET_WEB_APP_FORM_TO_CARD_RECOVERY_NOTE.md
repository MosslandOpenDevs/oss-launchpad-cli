# Preset web-app form-to-card recovery note

Use this note when the first generated web-app demo proof breaks between the starter form and the first visible result card.

## Recovery order

1. keep one form,
2. keep one primary action,
3. restore one believable result card,
4. confirm one visible download or handoff target.

## Proof loop

- rerun the same preset-specific smoke path
- verify the same form fields still map to the same result-card copy
- verify the same report/download target is still visible
- record the exact blocker before widening scope

## Scope boundary

Do not add extra screens, tabs, or secondary actions until the first form-to-card lane is stable again.
