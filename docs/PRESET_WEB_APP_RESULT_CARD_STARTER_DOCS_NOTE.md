# Web-app preset result card starter-doc note

For the first believable `web-app` preset proof, keep the result card narrow:

- one primary status
- one obvious download or export target
- one visible starter doc to open next (`docs/landing-page-brief.md` or `docs/information-architecture.md`)

This keeps the first result-card slice UI-first, reviewable, and easy to demo without pretending the whole app is finished.
