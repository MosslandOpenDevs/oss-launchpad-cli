# PRESET_WEB_APP_UI_PROOF_START

Use this when a `web-app` scaffold needs the smallest believable UI-first proof loop.

## Start order

1. Open `docs/landing-page-brief.md`
2. Open `docs/information-architecture.md`
3. Run `sh demo/run_demo.sh`
4. Compare the demo script output against the landing brief before widening scope

## First believable proof

Treat this pair as the day-zero proof bundle:
- visible proof asset: `docs/landing-page-brief.md`
- reproducible check asset: `demo/run_demo.sh`

## Keep it small

Before the first public push, prefer one landing flow with one smoke command over multiple half-specified screens.
