# Preset web app result card report download scope

Keep the first web-app proof narrow: one result card, one primary report-download action, and one matching exported bundle.

UI/UX-first rule:

1. The form should lead to one obvious result state instead of a multi-screen tour.
2. The result card should expose one believable primary action before secondary polish.
3. The downloaded/exported artifact should match the same result card copy and status.
4. If browser automation is flaky, replay the smallest passing form -> card -> download path before widening coverage.
