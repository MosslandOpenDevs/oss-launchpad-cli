# Preset web-app result-card scope note

For the `web-app` preset, keep the first believable UI proof narrow: one intro-first page, one primary form, and one reviewable result card before adding secondary navigation, dashboards, or multi-step flows.

Treat the exported starter docs, demo script, and browser automation as one proof lane. The result card should echo the submitted input clearly enough for a reviewer to compare the UI, the docs, and the Playwright path without guessing.

Validation stays simple: scaffold once, inspect the generated `docs/landing-page-brief.md` and `docs/information-architecture.md`, then keep browser proof reproducible before widening the preset surface.
