# Preset first backlog proof

Use this note when the scaffold already exists and you want the shortest path from generated starter files to a believable first issue backlog.

## What to turn into issues first

### ai-agent
- turn `evals/smoke_cases.jsonl` into the first evaluation coverage issue
- turn `docs/launch-plan.md` into the first public milestone issue

### web-app
- turn `docs/information-architecture.md` into the first UX/content issue
- turn `docs/launch-plan.md` into the first launch-readiness issue

### python-lib
- turn `docs/api-surface.md` into the first API polish issue
- turn `docs/launch-plan.md` into the first packaging/release issue

## Fast proof check

A believable first backlog should show:

1. one issue grounded in a generated proof asset,
2. one issue grounded in launch planning,
3. wording specific enough that a contributor could pick it up without re-reading the preset.
