# Preset web demo result card

Use this after the first believable `web-app` proof passes and you need a compact review card.

## What to show

- the screen or flow that matches `docs/landing-page-brief.md`
- the UX checks that already passed from `docs/ui-ux-checklist.md`
- the next highest-priority gap from `docs/information-architecture.md`

## One-line status

`Web demo proof is visible, the landing brief and UX checklist align, and the next gap stays scoped to one IA improvement.`

## Why this matters

A first public proof for a web preset should look concrete without pretending the whole app is production-ready.
