# PRESET_WEB_APP_RESULT_CARD_DOWNLOAD_BLUEPRINT

Use this note when the generated `web-app` preset is being turned into the first believable UI proof.

## Keep the proof narrow

Stay inside one path:

1. one input form,
2. one result card,
3. one obvious download/export target.

Do not widen into multi-screen launch claims yet.

## Why this blueprint exists

- The first result card should explain what happened without extra navigation.
- The download/export target should be visible from the same card.
- The maintainer should be able to validate the slice with one reproducible command and one visual review pass.

## Minimum review

Before claiming the proof is ready, confirm:

- the primary action creates or reveals one result card,
- the same card keeps one believable download/export cue,
- the README/demo script still describe that single path honestly.
