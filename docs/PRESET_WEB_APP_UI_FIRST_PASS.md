# web-app preset UI first pass

Use this note right after `oss-launchpad init ... --preset web-app` and before the first public push.

## First-pass order

1. Open `README.md` and `docs/landing-page-brief.md` together.
2. Replace placeholder value statements with the real product promise.
3. Turn `docs/ui-ux-checklist.md` into a small, testable happy-path checklist.
4. Make sure `demo/run_demo.sh` can demonstrate the same landing story without extra narration.
5. Confirm `docs/information-architecture.md` still matches the visible landing flow.

## Small proof rule

The first manual commit should usually show one visible UI proof asset plus one reproducible review asset, not a full launch rewrite.
