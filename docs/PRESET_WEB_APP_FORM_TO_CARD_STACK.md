# Web-app form-to-card proof stack

Keep the first generated web-app proof narrow and reviewable:

1. Review `docs/ui-ux-checklist.md` and `docs/landing-page-brief.md` before editing generated UI files.
2. Make one visible form input -> result card flow believable before adding extra screens.
3. Re-run the printed review/demo commands after the edit so the first proof still has one visible action and one reproducible artifact.
4. Use Playwright checkpoints only after the form, card, and download handoff stay stable by inspection.
