# Web-app preset result-card one-download rule

Use this note when the first generated web-app proof already has a visible result card and you need a narrow next check.

Keep the proof lane honest:

- one primary input form
- one reviewable result card
- one obvious download/export action
- one reproducible review command

If a change adds more than one visible result state, split it into a later pass instead of expanding the first proof commit.
