# Preset first-proof review sequence

Use this note after `oss-launchpad init` creates the scaffold and before the first manual commit.

## Sequence

1. Run the printed preset-specific validation command.
2. Open the printed proof-review command pair.
3. Confirm one visible proof asset and one reproducible check asset are both present.
4. Keep the first manual commit scoped to that proof pair.

## Pass signal

The scaffold is ready for a believable first manual commit when the README, the preset proof asset, and the reproducible command all line up without extra placeholder claims.

## Why this exists

Maintainers often see the generated files but still hesitate on the first real edit. This sequence turns the generated proof commands into a small, reviewable first-commit plan.
