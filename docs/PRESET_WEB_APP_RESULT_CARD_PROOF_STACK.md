# PRESET WEB APP RESULT CARD PROOF STACK

Use this note when the first `web-app` proof must stay aligned with UI/UX-first scope and Playwright-stable evidence.

## Stack order
1. One form action.
2. One believable result card.
3. One visible download or handoff target.
4. One deterministic browser-proof checkpoint bundle.

## Guardrails
- Keep the first card copy outcome-first, not feature-list-first.
- Do not widen to multi-screen flows before the first result card is reproducible.
- Preserve stable selectors/checkpoints before adding polish states.
