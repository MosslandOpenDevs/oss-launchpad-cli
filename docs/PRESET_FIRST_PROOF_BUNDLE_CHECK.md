# Preset First Proof Bundle Check

Use this after `oss-launchpad init` when you want to verify that the generated proof files already form a believable starter bundle.

## Check sequence

1. Open the preset-specific README proof asset.
2. Open the paired validation or demo asset from the same preset.
3. Confirm the first proof status command still names both files honestly.
4. Keep the public status line scoped to the generated bundle, not the whole product roadmap.

## Bundle lens by preset

- `ai-agent` — prompt/eval/demo proof
- `web-app` — landing brief/UI checklist/demo proof
- `python-lib` — example/test/API-surface proof

## Exit signal

The generated files already show one visible proof asset plus one reproducible check asset, so the scaffold is ready for the first manual repo update.
