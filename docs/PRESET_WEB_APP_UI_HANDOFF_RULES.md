# PRESET_WEB_APP_UI_HANDOFF_RULES

Use this note when a `web-app` scaffold already has its first landing brief and information architecture draft, and you need a compact UI handoff before implementation starts.

Keep the handoff small and reviewable:

1. Confirm the landing page brief still names the primary user, core promise, and first CTA.
2. Confirm the information architecture still matches the same happy path and does not introduce extra screens without proof.
3. Keep the demo script aligned with that same happy path so the first UI proof is reproducible.
4. If the UI changed materially, rerun the printed `web-app` smoke command before posting the handoff.

The goal is not visual perfection. The goal is a believable first UI proof bundle that another maintainer can verify quickly.
