# PRESET_WEB_DEMO_FORM_RESULT_STABILITY

Use this note when the first web-app demo proof adds or revises the initial input form and result card.

## Rule

Keep the first proof lane limited to:

1. one input form,
2. one submit action,
3. one result card,
4. one smoke command,
5. one reviewer-visible artifact.

## Why

This follows a UI/UX-first, stability-first approach: the first public proof should be obvious, reviewable, and easy to replay before adding secondary screens.

## Handoff

If a change touches more than one user goal, split it into separate proof slices before adding more starter guidance.
