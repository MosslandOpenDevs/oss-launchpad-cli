# Preset First Issue Checklist

Use this checklist right after the first believable proof command succeeds for a freshly generated scaffold.

## Goal

Turn scaffold proof into a small, reviewable first backlog issue without reopening every generated file.

## Checklist

1. Record the preset name and the exact proof command you ran.
2. Name the first edited file pair that best shows real customization.
3. Capture one proof artifact: test output, example run output, or generated file diff.
4. Write one issue sentence for the next improvement, not the whole roadmap.
5. Keep the issue scoped to the generated preset, unless the proof exposed a shared template bug.

## Copy-ready issue stub

- **Preset:** `<preset>`
- **Proof command:** `<command>`
- **Proof artifact:** `<test output | example run | diff>`
- **Next issue:** `<single next improvement>`

## Exit rule

If you cannot name the proof command and one proof artifact yet, do not draft the issue as if the scaffold is already validated.
