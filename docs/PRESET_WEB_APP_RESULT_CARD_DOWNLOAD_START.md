# PRESET_WEB_APP_RESULT_CARD_DOWNLOAD_START

Use this note when a web-app preset change needs the shortest proof path for a form-first demo:

1. keep one primary input form,
2. render one reviewable result card,
3. expose one obvious download/export action from that same card,
4. verify the flow before widening the UI surface.

This keeps demo work aligned with UI/UX-first scope control and Playwright-style checkpoint proof.
